# Request models and examples

## General conventions

- The request and response media type is JSON.
- IDs belong to Investran; they are not business keys generated by the client.
- Use the lookup and UDF endpoints to discover valid IDs before writing data.
- Entity writes may depend on `Version` for optimistic concurrency control.
- UDF values use `{ "id": <field-id>, "value": "<value>" }`.
- A successful create operation normally returns the created Investran DTO with its assigned ID.

## UDFs

Value sent in the request:

```json
{
  "id": 123,
  "value": "Exemplo"
}
```

Definition returned by a `/udfs` endpoint:

```json
{
  "id": 123,
  "name": "Business Unit",
  "entityType": "Investor",
  "required": true,
  "values": ["A", "B"]
}
```

Use `?required=true` to request only required definitions.

## Create an Investor

```http
POST /api/investor HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "name": "Example Investor",
  "nameAlias": "EXAMPLE",
  "domainId": 1,
  "entityTypeId": 2,
  "reviewStatusId": 1,
  "contactOrganizationId": 1001,
  "contactIndividualId": null,
  "taxId": "<redacted>",
  "udfs": [
    { "id": 123, "value": "A" }
  ]
}
```

The controller can associate an existing Organization or Individual contact when its corresponding ID is supplied.


### Allocation behavior

- For the “No Allocation” system rule, the controller creates a placeholder allocation internally.
- For other rules, explicit `investorAllocations` can be supplied.
- The allocation extension can calculate allocations before the batch is published.

### Batch workflow

```text
POST /api/batch
  → returns the batch created in Held status and its ID
GET /api/batch/{id}
  → check the internal journal entries and transactions
PUT /api/batch/status/post/{id}
  → post only after reconciliation and approval
```

## Update and delete

Update requests use the resource ID in the path and a complete or nearly complete model in the body:

```http
PUT /api/investor/1001
Authorization: Bearer <token>
Content-Type: application/json
```

Delete requests call Investran's native `Remove` operation. They do not necessarily behave like a simple database deletion and can fail because of relationships, permissions, workflow, or referential integrity rules.
