# Operational Guide - Name

Use this control block for any guide that tells a support or operations user to diagnose, configure, run, restart, recover, or validate a process. Keep it near the top of the page. Do not mark a procedure approved until its steps have been exercised in the stated scope.

## Document control

| Field | Value |
|---|---|
| Status | Draft / Under validation / Approved / KT pending |
| Technical owner | Responsible person or role; otherwise “To be confirmed” |
| Functional owner | Responsible person or role; otherwise “To be confirmed” |
| Scope and environment | Product/version and environments covered; state what remains unknown |
| Last validation | Date, environment, and controlled execution result; otherwise “Not validated” |
| Next review | Date or a clear event that triggers review |
| Evidence | Ticket, change, sanitized output, or test supporting the current instructions |

## Procedure quality

Include purpose, impact, prerequisites and approvals, diagnosis, steps, expected result, business validation, recovery or rollback, evidence to retain, and stop/escalation criteria. For purely conceptual pages, use the component template instead.
